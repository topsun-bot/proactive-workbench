## 4. 核心场景流程：「明天早上八点提醒带伞」
1. 用户输入文字：“明天早上八点提醒我带伞”。
2. **calendar**：解析出“明天 08:00（本地时区）”。如果结果不晚于当前时间，不直接设置，先问用户是否改到下一个 08:00。
3. **weather**：查询明天 08:00 前后的降水概率（地点见待定问题）。
4. **alarm**：在明天 08:00 设置提醒，文案按天气结果来定：
   - 预计有雨（降水概率 ≥ 阈值，阈值【假设】暂定 50%）：“今天可能下雨（降水概率 X%），记得带伞。”
   - 预计无雨：仍按用户要求设提醒，文案写“今天降水概率 X%，可能用不上伞，带不带你定”。【推断】用户明确要求了提醒，不能因为天晴就不提醒。
   - 天气查询失败：仍按原时间设置提醒，文案用“记得带伞（天气暂时查不到）”，并告诉用户查询失败。不能编造天气数值。
5. 设置完成后，向用户回显：提醒时间、天气结论和数据来源（真实或模拟）。
6. 【假设】触发前再查一次天气并更新文案，提前多少分钟待定。

## 6. 验收标准
- [ ] 在 Linux 上输入“明天早上八点提醒我带伞”，能生成一条定在次日 08:00（本地时区）的提醒。
- [ ] 天气返回有雨时，提醒文案里有“带伞”和降水概率。
- [ ] 天气返回无雨时，提醒照样设置，文案说明降水概率低。
- [ ] 天气查询失败时，提醒照样设置，文案和回显都说明“天气查不到”，界面上不出现编造的数值。
- [ ] 解析出的时间已经过去时，不会静默设置，而是先问用户。
- [ ] 使用模拟天气数据时，回显和提醒里都标注“模拟数据”。
- [ ] 到点后能弹出桌面通知；提醒可以查看、可以取消。
- [ ] 首版工具和场景以 `config/scope.yaml` 为准，代码能读取这个文件。
